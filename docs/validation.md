# การกันข้อมูลและรูปแบบช่องกรอก (Input Validation)

เอกสารนี้อธิบายวิธีที่ระบบป้องกัน 2 เรื่อง

1. **ข้อมูลแปลกที่หลุดเข้ามา (Runtime defense)** — ข้อมูลจากฐานข้อมูล/รีลไทม์ที่ผิดรูป
   (ค่าว่าง, ตัวอักษรในช่องตัวเลข, `null`, วันที่เสีย) จะไม่ทำให้หน้าจอ error/ค้าง
2. **การกรอกข้อมูลผิดรูปแบบ (Input validation)** — ผู้ใช้กรอกค่าที่ไม่ควรลงช่องนั้น
   เช่น ใส่ตัวเลขในช่องชื่อ หรือใส่ `abc` ในช่องราคา/จำนวน ระบบจะฟ้องรายช่องและไม่ให้บันทึก

---

## 1) กฎการตรวจรายช่อง (ผู้ใช้กรอก)

| ช่อง | หน้า | อนุญาต | ห้าม / บล็อก | ข้อความ error ตัวอย่าง |
|---|---|---|---|---|
| อีเมล | Login, Register | `ชื่อ@โดเมน.tld` (regex) | ช่องว่าง, ไม่มี `@`/จุด, เกิน 254 ตัว | รูปแบบอีเมลไม่ถูกต้อง |
| รหัสผ่าน | Login, Register | 6–72 ตัว | เว้นวรรค, สั้นกว่า 6, ยาวเกิน 72 | รหัสผ่านห้ามมีช่องว่าง |
| ชื่อผู้ใช้ (username) | Register | อักษรไทย/อังกฤษ, ตัวเลข, `_` ยาว 3–30 | เว้นวรรค, อักขระพิเศษ | ห้ามเว้นวรรคหรือใช้อักขระพิเศษ |
| ชื่อ-นามสกุล / ชื่อร้านค้า | Register, Profile | อักษรไทย/อังกฤษ, ช่องว่าง, `.` `-` ยาว 2–100 | **ตัวเลข**, อักขระพิเศษ (`@#$%`), emoji | ชื่อห้ามมีตัวเลข |
| เบอร์โทรศัพท์ | Register, Profile | ตัวเลข 9–10 หลัก (ตัด `-`, ช่องว่าง, `()` ได้) | ตัวอักษร, สั้น/ยาวเกิน | เบอร์โทรต้องเป็นตัวเลขเท่านั้น |
| สถานที่ (places/address) | Register, Profile | ข้อความว่างได้ ยาว ≤ 200 | เกิน 200 ตัว | สถานที่ต้องไม่เกิน 200 ตัวอักษร |
| ชื่อสินค้า | Seller เพิ่ม/แก้ไข | ข้อความ 1–100 ตัว (มีตัวเลขได้ เช่น "เสื้อยืด 2XL") | ว่าง, เกิน 100 | กรุณากรอกชื่อสินค้า |
| ราคา | Seller เพิ่ม/แก้ไข | ตัวเลข ≥ 0, ทศนิยม ≤ 2 ตำแหน่ง, ≤ 7 หลัก | `abc`, `1e3`, ค่าติดลบ, ทศนิยมเกิน 2 ตำแหน่ง | ราคาต้องเป็นตัวเลข เช่น 250 หรือ 250.50 เท่านั้น |
| จำนวน (สต็อก) | Seller เพิ่ม/แก้ไข | เลขจำนวนเต็ม ≥ 0, ≤ 6 หลัก | `abc`, ทศนิยม, ค่าติดลบ | จำนวนต้องเป็นเลขจำนวนเต็มไม่ติดลบ เช่น 5 |
| หมวดหมู่ / ไซส์ / สี | Seller เพิ่ม/แก้ไข | ว่างได้ ยาว ≤ 50 | เกิน 50 ตัว | หมวดหมู่ไม่เกิน 50 ตัวอักษร |
| รายละเอียดสินค้า | Seller เพิ่ม/แก้ไข | ว่างได้ ยาว ≤ 2000 | เกิน 2000 ตัว | รายละเอียดไม่เกิน 2000 ตัวอักษร |

**หมายเหตุ**

- หน้า Login **ไม่มีช่องชื่อ** จึงไม่ได้ตรวจ "ห้ามตัวเลขในชื่อ" ที่หน้านี้
- หน้า "ดูรายการสินค้า Seller" (`SellerProductsPage`) ไม่มีช่องกรอกข้อความ มีเพียงปุ่มลบ + กล่องยืนยัน
- ช่องตัวเลข (ราคา/จำนวน) ใช้ `type="number"` ช่วยกันการพิมพ์ตัวอักษรในเบราว์เซอร์อยู่แล้ว และมี JS ตรวจซ้ำอีกชั้น

## 2) ฟังก์ชันที่ใช้ตรวจ (`src/lib/validators.js`)

| ฟังก์ชัน | หน้าที่ |
|---|---|
| `hasDigit(value)` | true ถ้ามีตัวเลข 0–9 ปะปน |
| `isEmail(value)` | true ถ้ารูปแบบคล้ายอีเมล |
| `isNumeric(value)` | true ถ้าเป็นตัวเลขที่คำนวณได้ (ไม่ใช่ NaN/Infinity) |
| `isNonNegativeInt(value)` | true ถ้าเป็นเลขจำนวนเต็ม ≥ 0 (ใช้กับจำนวน) |
| `isValidPrice(value)` | true ถ้าเป็นราคา ≥ 0 ทศนิยม ≤ 2 ตำแหน่ง |
| `cleanDigits(value)` | ตัดทุกอย่างที่ไม่ใช่ตัวเลข (ใช้กับเบอร์โทร) |
| `isValidName(value)` | true ถ้าชื่อมีเฉพาะ อักษร/ช่องว่าง/`.`/`-` |
| `isValidUsername(value)` | true ถ้า username ใช้เฉพาะอักษร/ตัวเลข/`_` |
| `lengthOf(value)` | ความยาวหลังตัดช่องว่างหัว-ท้าย |

รูปแบบการใช้งานในหน้า: เก็บ `errors` เป็น object รายช่อง ตรวจตอนกด submit
ถ้ามี error จะไม่ส่งข้อมูล และแสดงข้อความใต้ input พร้อมขอบแดง (`<FormInput :error="..." />`)
เมื่อผู้ใช้เริ่มพิมพ์ใหม่ error จะถูกล้างทันที

## 3) การกันข้อมูลผิดรูปตอนแสดงผล (Runtime defense)

| จุด | ปัญหาเดิม | วิธีกัน |
|---|---|---|
| `formatTHB` / `formatDate` (`lib/format.js`) | โชว์ `NaN บาท` / `Invalid time value` | เพิ่ม `toNumber()` และคืน `-` เมื่อวันที่ไม่ถูกต้อง |
| ยอดรวมในตะกร้า (`stores/cart.js`) | `NaN` กระจายทั้งหน้า | คูณ/บวกผ่าน `toNumber()` |
| ยอดขาย/ยอดออเดอร์ (`SellerDashboardPage`, `SellerOrdersPage`) | ยอดรวมเพี้ยน | รวมผ่าน `toNumber()` |
| เรียงราคา (`HomePage`) | sort ได้ผลแปลก | เทียบด้วย `toNumber()` |
| ราคารวมหน้าสินค้า (`ProductDetailPage`) | `NaN` | คูณผ่าน `toNumber()` |
| หน้าชำระเงิน (`CheckoutPage`) | สินค้าถูกลบ → TypeError | ตรวจ `item.product` ก่อนใช้ |
| สถานะออเดอร์ไม่รู้จัก (`SellerOrdersPage`) | ปุ่มอัปเดตเป็น `undefined` | ซ่อนปุ่มถ้า `statusIdx < 0` |
| ชื่อสินค้า/ร้าน/ผู้ซื้อ/สี (`ProductCard`, `ChatRoom`, chat lists, dashboard) | แสดงค่าว่าง/พังเมื่อ `null` | ใส่ค่า fallback (`|| 'สินค้า'`, `|| 'ร้านค้า'`, `|| 'ผู้ซื้อ'`) |
| วันที่ในแชท (`SellerChatListPage`) | โชว์ ISO ดิบ | ผ่าน `formatDate()` |
| Realtime แจ้งเตือน (`stores/notification.js`) | payload ว่างทำให้ error | ตรวจ `payload?.new?.id` ก่อนเข้า state |
| เริ่มแอป (`main.js`) | ติดต่อ Supabase ครั้งแรกไม่สำเร็จ → หน้าไม่ขึ้น | `auth.init().catch(...).finally(mount)` + `app.config.errorHandler` |

## 4) วิธีทดสอบ

1. รัน build ให้ผ่าน
   ```bash
   npm run build
   ```
2. เปิดหน้า dev แล้วลองกรอกค่าผิด:
   - **สมัครสมาชิก**: ชื่อเป็น `สมชาย123` / `Test@#$` → ต้องขึ้น error ใต้ช่องและกดสมัครไม่ผ่าน
   - **เบอร์โทร**: `08x-123-4567` → เบอร์โทรต้องเป็นตัวเลขเท่านั้น
   - **login**: `abc` (ไม่ใช่อีเมล), รหัสผ่านมีช่องว่าง → ฟ้องก่อนยิง API
   - **เพิ่ม/แก้ไขสินค้า**: ราคา `abc` หรือ `12.345`, จำนวน `2.5` / `-1` → ฟ้องใต้ช่อง
   - **โปรไฟล์**: ชื่อมีตัวเลข → ฟ้อง (กันการบันทึกผ่านหน้าอื่น)
3. ตรวจว่าเมื่อพิมพ์แก้ error หายไป และบันทึกผ่านเมื่อทุกช่องถูกต้อง
